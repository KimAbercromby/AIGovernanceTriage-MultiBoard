How it works

Governance travels with the system

The AGPI and risk engines classify a system once. A governance relay then carries that classification across the existing forums, with configurable forum names, a decision-ready evidence plan that feeds the Decision-Ready Paper (WCC-AIG-38), an Excel-ready Register row and a separate planned-gate export — the end-to-end visibility that an integrated governance pathway needs.

Authority stays with each forum. The assurance board carries continuity and issues one assurance opinion; it does not replace strategic, technical, commercial or release authority. Final accountability stays with the Service Owner, SRO or delegated authority.

    Export the result

    Each button downloads the triage result in a different form: the Register row, the planned gate route, the artefact handoff, or a full summary.     Lifecycle end

    Retire or decommission an AI system

    Retirement is a governance gate in its own right, not a triage. This mode does not score AGPI or plan a deployment route. It runs the decommission gate, scaled to the system's current governance priority, and produces a Gate Log event (WCC-AIG-36) and a Decision Record stub (WCC-AIG-16) keyed to the existing AIR-ID.

    Gate Log event (WCC-AIG-36)

    Append this event to the Gate Log, keyed to the AIR-ID. The Register Status becomes Decommissioned only when the gate is complete; until then it reads "Retirement: pending gate".
